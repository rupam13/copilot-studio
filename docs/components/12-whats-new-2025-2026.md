### 1. Copilot Credits — New Licensing Currency
**Status:** GA since **September 1, 2025**  
**Replaces:** Message-based consumption model

#### What Changed
Microsoft replaced the "messages" model with **Copilot Credits** as the universal consumption currency across all Copilot Studio capabilities. Every agent action — answering a question, calling a tool, retrieving knowledge, executing a flow — now consumes a defined number of credits based on the type of capability used.

#### Credit Consumption by Capability Type

| Capability | Credits Consumed | Notes |
|---|---|---|
| Classic answer (scripted topic response) | **1 credit** | Lowest cost — deterministic authored paths |
| Generative answer (from knowledge source) | **2 credits** | Includes retrieval + synthesis |
| Agent action (tool call) | **5 credits** | Per tool invocation |
| Agent flow action (per 100 actions) | **13 credits** | Power Automate steps in the flow |
| AI tool — Basic model | Lower tier | Simple reasoning tasks |
| AI tool — Standard model | Mid tier | Complex reasoning, multi-step |
| AI tool — Premium model (GPT-5) | Higher tier | Advanced reasoning, long context |
| Computer Use action | Highest tier | UI automation — most expensive per action |

#### What This Means for Your Designs
- **Generative answers cost 2× classic answers** — where scripted topics work, use them
- **Tool calls are expensive** — avoid calling tools when knowledge source answers suffice
- **Generative orchestration + multi-tool chains** accumulate credits fast on high-volume agents
- **Computer Use is premium** — reserve for systems with no API; don't use it where a connector exists
- **M365 Copilot licence holders** get credit-free access when the agent runs as the licensed user's identity

#### Rate Limits by Pack Tier (still relevant for throttling)

| Message Packs | RPM | RPH |
|---|---|---|
| 1–10 | 50 | 1,000 |
| 11–50 | 80 | 1,600 |
| 51–150 | 100 | 2,000 |

> **Design rule:** Model your expected credit consumption BEFORE building. A generative orchestration agent calling 3 tools per turn on 10,000 users/day will exhaust capacity you didn't plan for. Use the [Microsoft agent usage estimator](https://aka.ms/copilot-studio-estimator) to calculate before committing to an architecture.

### 2. GPT-5 and Advanced Model Support
**Status:** GA  
**When available:** Integrated into Copilot Studio model selection

#### What Changed
Copilot Studio now supports multiple model tiers including **GPT-5** and **Anthropic Claude Opus 4.8**. Previously, the platform used a single Microsoft-managed model with no selection. Makers can now choose the model for custom prompt actions and for the agent reasoning layer.

#### Model Tiers at a Glance

| Tier | Models | Best For | Credit Cost |
|---|---|---|---|
| **Basic** | Lightweight models | Simple classification, extraction, structured output | Lower |
| **Standard** | GPT-4-class models | Complex reasoning, multi-step flows, nuanced instructions | Mid |
| **Premium** | GPT-5, Claude Opus 4.8 | Long context, deep reasoning, ambiguous enterprise language | Higher |

#### When to Use Each Tier
- **Basic:** Classifying ticket categories, extracting entities from forms, simple summarisation
- **Standard:** Most production agents — conversational reasoning, tool selection, multi-step planning
- **Premium:** Complex legal/financial analysis, very long documents, agents that must reason across many tools simultaneously
- **BYO models (Azure AI Foundry):** Domain-specific fine-tuned models, specialised speech/vision — crosses into pro-code territory

> ⚠️ **The rule that hasn't changed:** Don't reach for a bigger model to fix a grounding or instruction problem. Fix the source first, then consider the model. Upgrading from Standard to Premium to fix hallucination costs 30–50% more per turn and usually doesn't fix the underlying grounding issue.

### 3. Computer Use — Agents That Operate Any UI
**Status:** GA since **May 2026** (Preview from late 2025)

#### What It Is
Computer Use allows a Copilot Studio agent to interact with **desktop applications and websites directly** — moving a virtual mouse, clicking buttons, typing into fields, reading screen content, and navigating forms — without any API or connector.

#### What This Unlocks
- Automate **legacy ERP systems** (SAP, Oracle) that have no modern API
- Operate **internal web apps** built on 2008 ASP.NET that will never get a connector
- Fill out **government portals and third-party forms** that have no integration path
- Perform **end-to-end browser automation** as part of a larger agent workflow

#### How to Use It

```
1. In your agent's tool list → Add Tool → Computer Use
2. Describe the task in natural language:
   "Navigate to the SAP portal at https://..., log in with the service account,
    open the Purchase Orders module, search for PO number {Topic.poNumber},
    and extract the approval status and approver name."
3. The agent executes this in a secure sandboxed browser session
4. Results are returned as structured output to the next step in your flow
```

#### When to Use vs When NOT to

| Use Computer Use | Don't Use Computer Use |
|---|---|
| System has NO API and NO connector | Connector exists — use it instead |
| Legacy on-premise app never getting modernised | Public API available — more reliable |
| Third-party form/portal with no integration | Internal system that IT can expose via API |
| Regulatory/compliance portal with web-only access | High-frequency, high-volume actions (cost + speed) |
| One-time or low-frequency tasks | Actions requiring sub-second latency |

> ⚠️ **Limits:** Computer Use is the most expensive capability (credits). UI automation is inherently more fragile than API integration — UI changes break flows silently. Always wrap Computer Use actions in monitoring and a human-approval step for anything consequential.

### 4. Model Context Protocol (MCP) — 1,400+ Integrations
**Status:** GA  
**Available from:** 2025

#### What It Is
The Model Context Protocol (MCP) is an open standard that allows agents to securely connect to a wide range of external tools, data sources, and knowledge servers through a **standardised interface** — without building a custom connector for each.

#### What This Replaces / Complements

| Before MCP | With MCP |
|---|---|
| Custom connector per system | One MCP server exposes multiple tools |
| OpenAPI definition required | MCP manifest describes tools in agent-native format |
| Connector payload limits apply | MCP handles its own transport |
| Power Platform connector ecosystem (1,000+) | MCP ecosystem (1,400+ systems, growing) |

#### How to Add an MCP Tool

```
Agent authoring → Tools → + Add Tool → MCP Tool
→ Paste MCP server URL or select from Microsoft's MCP catalogue
→ Authenticate (OAuth 2.0 or API key)
→ Select which tools from the MCP server to expose to your agent
→ Write tool descriptions (same rules as any other tool — model reads these)
```

#### Common MCP Integrations Available
- GitHub, Jira, Confluence, Linear (engineering tools)
- Salesforce, HubSpot (CRM)
- Slack, Discord (messaging)
- Google Drive, Dropbox (file systems)
- Stripe, QuickBooks (payments/finance)
- PostgreSQL, MongoDB (databases directly)
- Docker, Kubernetes (infra)

> **Design note:** MCP tools still require clear descriptions for the orchestrator. Adding 50 MCP tools and expecting the model to figure out routing is the same mistake as having 50 connectors with bad descriptions. Write tool descriptions; control the tool list to ~15–20 maximum.

### 5. Microsoft IQ — Organisational Knowledge Layer
**Status:** Preview (Production-Ready Preview from June 2026)

#### What It Is
Microsoft IQ is an enterprise knowledge layer that gives agents **secure, contextual access to your organisation's Microsoft 365 data** — emails, calendar events, files, Teams messages, SharePoint content — respecting existing permissions.

#### What Agents Can Do With Microsoft IQ

| M365 Source | What Agent Can Access | Example Use |
|---|---|---|
| SharePoint / OneDrive | Files, documents, wikis | "Find the latest IT policy document for VPN access" |
| Outlook | Emails, calendar events | "What meetings do I have tomorrow?" |
| Teams | Messages, channels, meeting transcripts | "Summarise what was decided in the project Kickoff meeting" |
| People / Org chart | Directory, reporting lines, roles | "Who is the finance approver for APAC?" |
| Viva / Learning | Training records, certifications | "Has this employee completed the GDPR training?" |

#### How It Differs from Standard Knowledge Sources

| Standard Knowledge Source | Microsoft IQ |
|---|---|
| You upload files or point at URLs | Connects live to M365 data graph |
| Static or slow-refresh (4–6 hr) | Near real-time |
| No user context | Respects user's own M365 permissions |
| Any file format you upload | M365 native content |
| Works without M365 Copilot licence | Requires M365 Copilot licence |

> **Licence requirement:** Microsoft IQ features require a **Microsoft 365 Copilot licence**. Agents using Microsoft IQ run as the authenticated user's identity — user sees only what they are permitted to see in M365.

### 6. Modular Skills — Reusable Agent Capabilities
**Status:** Preview (June 2026)

#### What It Is
Skills are **self-contained, reusable packages of instructions** — a named set of behaviours that multiple agents can share without duplicating configuration. Think of them as agent-level libraries or components.

#### Before and After

| Before Skills | With Skills |
|---|---|
| Duplicate instructions across agents | Define once, reference from N agents |
| Shared logic embedded in each agent's instructions | Skill is versioned, updated once, agents pick up change |
| No composability | Combine skills: Expense Policy Skill + Approval Routing Skill |
| Hard to audit and test per capability | Test each skill independently |

#### Example Skill Definition
```
Skill: ExpensePolicyAdvisor
Description: Knows all Contoso expense reimbursement rules and limits.
             Answers questions about what is reimbursable, thresholds by grade,
             receipt requirements, and submission deadlines.
Instructions: [embedded policy rules and limits]
Knowledge: Expense Policy SharePoint library
Tools: None
```

This skill can then be referenced by the IT Agent, the HR Agent, the Finance Agent, and the Employee Onboarding Agent — all sharing the same, centrally governed capability.

### 7. Real-Time Voice Agents
**Status:** GA (2026)  
**Replaces:** Basic telephony integration (text-to-speech bridging)

#### What Changed
Previously, voice in Copilot Studio meant converting text responses to speech through a telephony bridge — with all the limitations that implies (robotic voice, markdown read literally, cards invisible). Real-time voice agents are a fundamentally different capability.

#### What Real-Time Voice Agents Can Do
- Handle **natural spoken conversation** with interruptions, backchannels, hesitations
- Adapt **dynamically to conversation pace** — no turn-taking script required
- **Detect emotion and intent from tone** (with appropriate model)
- Support **complex multi-turn** customer service conversations
- Integrate with **Azure Communication Services** for call routing, PSTN

#### Authoring for Voice — What Changes

| Design Element | Web/Text Channel | Voice Channel |
|---|---|---|
| Response format | Rich text, bullets, markdown, cards | Short sentences, no markdown, no bullets |
| Card/button display | Adaptive Cards supported | Cards INVISIBLE — text fallback mandatory |
| Response length | Paragraph is fine | 1–2 sentences max per turn |
| Numbers/URLs | Display as-is | Must be spelled out: "Go to contoso dot com" |
| Silence handling | User just types | Agent must handle silence gracefully |
| Interruption | N/A | Agent must yield mid-sentence gracefully |

> **Design rule:** Design voice responses as SPEECH, not text. Every response must pass the "read aloud test" — read it aloud; if it sounds robotic or confusing, rewrite it.

### 8. Agent 365 — Unified Governance Control Plane
**Status:** GA (2026)

#### What It Is
**Agent 365** is Microsoft's unified control plane for IT admins and governance teams to manage, monitor, audit, and govern ALL agents in their tenant — across Copilot Studio, M365 Copilot, and connected agents.

#### What Admins Can Do in Agent 365

| Capability | Description |
|---|---|
| **Inventory all agents** | See every agent in the tenant — owner, last modified, published channels, status |
| **Agent Status Visibility** | See security and protection posture directly: auth gaps, DLP compliance, sensitivity settings |
| **Analytics Viewer Role** | Read-only access to agent performance data — separates operational visibility from configuration rights |
| **Kill switch / suspend** | Suspend or deactivate any agent from the control plane without touching the agent itself |
| **Usage & cost by agent** | Per-agent credit consumption, top users, peak hours, error rates |
| **Entra Agent ID integration** | Each agent has its own managed identity — auditable, revocable, scope-controlled |
| **Defender for Agents** | Real-time threat protection: prompt injection detection, data exfiltration alerts |
| **Purview audit log** | Every conversation turn, tool call, and data access logged for compliance |

#### The Governance Architecture (2026)

```

              │         AGENT 365               │
```

### 9. Entra Agent ID — Per-Agent Managed Identity
**Status:** GA (2026)

#### What It Is
Every Copilot Studio agent now gets its own **Entra managed identity** — an Agent ID — just like a service principal, but designed for agents. This replaces the pattern where agents inherited the maker's identity or ran as a generic service account.

#### What This Enables

| Old Pattern | With Entra Agent ID |
|---|---|
| Agent runs as maker's identity | Agent has its own named identity |
| Permissions = maker's permissions | Permissions = exactly what agent needs (least privilege) |
| Revoke agent access = revoke maker's rights | Revoke agent independently with zero side effects |
| Audit log shows "maker@contoso.com" | Audit log shows "IT Support Agent [AgentID: abc123]" |
| One compromised agent = maker account at risk | One compromised agent = isolated, revocable |

> **When to use:** Always, for any production agent accessing sensitive systems. Entra Agent ID makes your agent a first-class security principal with its own lifecycle, audit trail, and revocation path.

### 10. Agent Evaluation Framework
**Status:** GA (2026)  
**Replaces:** Manual test pane testing

#### What It Is
A systematic, automated testing framework that lets you define **evaluation sets** with expected inputs and outcomes, run them against your agent at scale, score results with a custom grader, and track quality over time.

#### How It Works

```
1. Define evaluation set:
   Input: "What is the VPN policy for remote workers?"
   Expected: Response mentions split-tunnelling policy, cites IT-SEC-017

2. Define grader:
   - Did response mention split-tunnelling? (Yes/No)
   - Did it cite the correct policy document? (Yes/No)
   - Was the response under 200 words? (Yes/No)
   - Score: (sum of Yes answers / total checks) × 100

3. Run evaluation against current agent version
   → Scores: 87/100 average across 50 test cases

4. Make a change (e.g., update knowledge source)
5. Re-run evaluation → Scores: 93/100
   → Proved improvement, safe to deploy
```

#### Evaluation Dimensions to Measure

| Dimension | What to Test | Target |
|---|---|---|
| **Accuracy** | Is the answer factually correct? | >90% |
| **Completeness** | Does it answer all parts of the question? | >85% |
| **Scope adherence** | Does it stay in scope (no hallucination outside KB)? | 100% |
| **Tool selection** | Did it call the right tool? | >95% |
| **Refusal quality** | For out-of-scope: does it refuse gracefully? | 100% |
| **Latency** | Does it respond within SLA? | >99% under X seconds |

> **Rule:** Run evaluation before and after EVERY change. The score difference is your proof of improvement (or the warning that you regressed). This is the only way to move from gut-feel to evidence-based agent management.

The June 2026 "New Agent Experience" is a redesigned authoring surface that restructures how you build agents, reflecting the new component model:

| Old Structure | New Structure |

| Topics list (primary) | **Instructions** (primary) |

### 12. Bring Your Own Models (BYOM) — Azure AI Foundry Integration
**Status:** GA (2026)  
**Requires:** Azure AI Foundry + pro-code extension

#### What It Is
Organisations can now connect **custom fine-tuned models** from Azure AI Foundry to Copilot Studio as the reasoning layer for specific agents or prompt actions.

#### When to Use BYOM

| Use Case | BYOM Appropriate? |
|---|---|
| Medical coding — domain-specific terminology | ✅ Yes — fine-tuned model dramatically outperforms general model |
| Legal contract analysis — jurisdiction-specific | ✅ Yes |
| Financial fraud detection — proprietary patterns | ✅ Yes |
| General IT helpdesk agent | ❌ No — GPT-5 handles this without fine-tuning |
| Customer FAQ agent | ❌ No — knowledge source grounding is sufficient |

> **Cost vs benefit:** Fine-tuning a model requires a substantial data curation effort, Azure AI Foundry expertise, and ongoing maintenance. Only worth it when domain-specific accuracy gaps cannot be closed with better instructions and knowledge sources.

### 13. WhatsApp Channel — Generally Available
**Status:** GA (late 2025)

#### What Changed
WhatsApp went from partner preview to generally available as a published channel. Integration is via **Azure Communication Services (ACS)** acting as the bridge between WhatsApp Business API and Copilot Studio.

#### Setup Architecture

```
WhatsApp Business Account
        │
        ▼
Azure Communication Services (ACS)
    Advanced Messaging module
        │
        ▼  (Event Grid webhook)
Copilot Studio Agent
        │
        ▼  (response)
Azure Communication Services
        │
        ▼
User's WhatsApp
```

#### WhatsApp-Specific Constraints

| Constraint | Detail |
|---|---|
| Message templates | Required for business-initiated messages (outside 24hr window) |
| Adaptive Cards | NOT supported — plain text and basic formatting only |
| Rich media | Images and documents supported; no interactive cards |
| 24-hour window | Free-form messaging only within 24hrs of user's last message |
| Character limit | 4,096 chars per message |
| Phone number | Must be WhatsApp Business verified number |
| Opt-in required | Users must opt in before you can initiate conversation |

> **Design for WhatsApp separately.** Your Teams agent cannot be copy-pasted to WhatsApp. Adaptive Cards don't render, rich formatting degrades, and the conversation model is different. Treat it as its own design effort with WhatsApp-native constraints.

### 14. SSO Consent Cards — Streamlined Authentication
**Status:** GA (2025)

#### What Changed
Previously, when an agent needed to authenticate a user for Entra ID–backed actions, it redirected the user to a browser sign-in page — breaking the conversation flow (especially in Teams mobile). SSO Consent Cards allow the authentication to happen **inline within the conversation** without a redirect.

#### Impact

| Before SSO Consent Cards | With SSO Consent Cards |
|---|---|
| Agent says "please sign in at this URL" | Consent card appears inline in chat |
| User leaves the conversation context | User taps "Approve" without leaving chat |
| Broken experience on Teams mobile | Works on desktop and mobile |
| High drop-off at authentication step | Significantly lower drop-off |

## 🎯 Interview-grade summaries

**"What is the biggest change in Copilot Studio in the last year?"**
> The platform has shifted from a low-code chatbot builder to an enterprise agent platform. The biggest practical changes are: (1) Copilot Credits replacing message-based billing — every capability now has a cost you need to model before you build; (2) Computer Use making agents capable of operating any UI, not just systems with APIs; (3) MCP giving access to 1,400+ systems through a standard protocol; and (4) Agent 365 giving enterprises a unified governance control plane across all agents in the tenant.

**"What is Copilot Credits and why does it matter for your architecture?"**
> It's the consumption currency that replaced "messages." Every capability has a credit cost — classic answers cost 1, generative answers cost 2, tool calls cost 5. This means architectural choices are now billing choices. A generative orchestration agent that calls 3 tools per turn costs 17 credits per conversation turn. At scale, that matters. You now have to balance capability against cost the same way you balance compute against cost in cloud architecture.

**"What is Computer Use and when would you NOT use it?"**
> Computer Use lets an agent interact with any UI — websites, desktop apps — the way a human would, using a virtual mouse and keyboard. It covers legacy systems that will never get an API. I would NOT use it when a connector or API exists — it's the most expensive capability, the most fragile (UI changes break it silently), and has the highest latency. It's the last resort, not the first choice.

**"What is Entra Agent ID?"**
> Each production agent now gets its own managed identity in Entra — its own security principal with its own permissions, audit trail, and revocation path. Previously, agents ran as the maker's identity or a generic service account. Now an agent is a named identity in your directory. If it's compromised, you revoke it without affecting anyone else. Every action it takes in downstream systems is logged under its identity, not a human's.

**"How has governance changed?"**
> Significantly. Agent 365 is a unified control plane where IT admins can see every agent in the tenant, its auth posture, usage metrics, and compliance status — and suspend any agent with one click. This is paired with Entra Agent ID for per-agent identity, Microsoft Defender for threat protection, and Purview for audit logging. In 2024, "governing an agent" meant setting DLP policies. In 2026, it means a full security principal lifecycle, real-time threat detection, and a compliance-grade audit trail.
