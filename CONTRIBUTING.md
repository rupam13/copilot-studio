# Contributing

Corrections and additions are welcome.

## What's most useful

1. **Product drift.** Copilot Studio changes monthly. If a page describes behaviour that no longer matches the product, open an issue with a link to the relevant Microsoft Learn page.
2. **Field patterns.** A pattern that worked (or failed) on a real deployment is worth more than a restated doc page.
3. **Interview questions.** If you were asked something these pages don't cover, add it.

## Style

- Concrete over abstract. Show the instruction, the flow, the failure.
- Trade-offs, not recommendations. Say what a choice costs.
- No marketing voice.
- Keep the page shape: what it is → when to use it → when not to → mistakes.
- Flag anything version-sensitive, and prefer linking to Microsoft Learn over restating numbers that will go stale.

## Process

1. Fork, branch (`docs/topic-name`)
2. Commit with a clear message
3. Open a PR describing what changed and why

## Not accepted

- Copy-pasted Microsoft documentation
- Screenshots of the product UI (they date within weeks)
- Anything containing tenant identifiers, real endpoints, or customer data
